지금 연출은 반짝이가 돌아가 "바겐세일 같다"는 평. 화면을 덮지 않고 **무기 칸에서 무겁게** 보여 준다(약 1.5초, 게임은 멈추지 않는다).

발견과 처리: 저격포 관통·이중 저격 버그 → T5c. 역장 뿌리 효과 없음, T1 뒤 스킬 재측정 값 → T6. 집광 약함 → T3 안에서 v [12.5, 25, 50, 125] → [50, 100, 200, 500] (측정 +8/+14/+26/+62, 잔열 +10/+20/+40/+99 의 0.65배. 적이 적으면 잔열보다 세고 많으면 거의 0 이라 더 올리지 않음, 남은 판단은 T8). 나머지 예산 밖 항목(구조 문제 2개, 값만 고칠 것, 기지 항목) → T8.
사용자 아이디어(2026-11-16): 매번 플레이 측정 대신 모든 수치를 "공격력 +1%와 같은 가치" 단위로 미리 환산해 두고, 처음에 한 번 영점을 맞춘 뒤로는 계산으로 수치를 정한다. 그 뒤 사용자가 체감으로 조정한다.
- 만들 것: `tools/value.js`(계산기)와 `docs/value.md`(사용자용 설명: 단위, 항목별 환산 계수, 쉬운 한국어, 휴대폰으로 읽기 좋게 짧게).
- 단위: 화력 가치 1 = 공격력 +1%. 생존(기지 체력·피해 감소·회복)과 성장(재화·강화 확률·조각)은 각각 따로 단위를 두고, 화력과의 교환 비율을 영점에서 정한다.
- 환산 식은 계수가 있는 식으로 둔다. 예:
  - 공격 속도 +x% = x × (1 + 적중 효과 비중 보정)
  - 추가 탄·연쇄·관통 = 추가로 맞는 적 수 기대값 × 그 피해 비율
  - 범위 = 맞는 적 수 기대값(적 밀도 가정에 따라)
  - 둔화 s% = 사거리 안에 머무는 시간 증가 1/(1−s) − 1 에 계수
  - 기절·밀어내기 = 같은 방식의 시간 환산
  - 치명타 = 기대값
  - 보스 피해 = 보스 피해 비중
  - 적 밀도와 보스 비중은 시간대(초반·중반·후반)별 가정값으로 둔다.
- 영점: 이미 있는 측정값에 계수를 맞춘다. 시나리오 벤치는 `tools/bench_summary.json`·`bench_report.txt`, 기지 항목 짝 생존은 `tools/balance_log.md`, 진화 스킬은 `tools/skill_eq_report.txt` 다. 맞춘 뒤 예측과 측정의 차이를 항목별로 보고한다(크게 어긋나는 항목은 이유와 함께).
- 출력: 모든 파츠·증강(등급별)·진화 노드(랭크별)의 화력 가치. 등급 예산(일반 0.25, 희귀 0.5, 영웅 1, 전설 2.5 × 같은 칸 종류의 영웅 평균)에서 크게 벗어나는 항목 목록. 수치는 바꾸지 않고 제안만 한다.
- `CLAUDE.md` 의 "밸런스 검증 방법"에 이 도구를 짧게 추가한다.

## [완료 2026-11-16] T4. 한 번에 때리는 적 수 제한과 관련 아이템

사용자 요청(2026-11-16): 레이저·산성처럼 범위 안의 적을 제한 없이 때리는 공격이 후반(적이 많을 때)에 너무 강하다. 최대 타격 수를 두고, 그것을 늘리거나 없애는 아이템을 만든다.
- 규칙: **범위로 한 번에 여러 적을 때리는 공격**은 한 번에 최대 N명까지만 피해를 준다. 고르는 순서는 기지에 가까운 적부터다. 연쇄·관통처럼 이미 개수가 정해진 공격은 그대로 둔다.
- 대상: 레이저 빔(옆 빔·지속 빔·상시 빔·프리즘 포함), 펄스 파동(초신성·반격 포함), 박격포 폭발(집속 포함), 산성 웅덩이(웅덩이 하나의 한 틱 기준), 용융선·불바다·잔광 같은 바닥 효과.
- 처음 값(T3 계산기로 확인 후 조정 가능): 레이저 6, 펄스 8, 박격포 8, 산성 6, 바닥 효과는 그 무기의 값.
  - 빔은 N번째 적에서 멈춰 보이게 그린다(흡수되는 느낌).
  - 무기 창에 "최대 N명"을 짧게 표시한다.
- 아이템:
  - 무기 파츠 `spread`: 최대 타격 수 +[1, 2, 3, 5], 최저 등급 일반. 이름은 쉬운 한국어로.
  - 무기 파츠 `nolimit`: 최대 타격 수 제한 없음, 전설만. 대신 공격력 −x% 로 대가를 둔다(사용자가 허락한 "깎는 대신 올리는" 방향). x 는 T3 계산기로 정한다.
  - 둘 다 한 칸을 쓰는 만큼의 가치가 되게 T3 계산기로 값을 맞춘다. 범위 공격이 아닌 무기에 달면 쓸모가 없으니, 파츠 설명이나 무기 창에서 "범위 무기 전용"이 보이게 한다.
- 검증:
  - `evo_test.js` 에 제한 검사를 넣는다(적 20명 앞에서 레이저가 6명만 맞힌다, `spread`·`nolimit`, 진화 스킬 효과도 제한된다).

- 박격포 (T5a 측정, `tools/skill_eq_report_t5a.txt`): 같은 무기 다섯 자루는 정예(few) 말고는 기준이 "못버팀"이고, 섞인 팀(`--mix`)도 물량은 못버팀, 표준은 박격포 공격력을 16배로 해도 팀 M* 가 1.2배라 "평평", 보스전·초반은 세 줄 모두 16배어치를 넘는다(">16"). 박격포는 공격력보다 폭발 횟수(처리량)가 한계라 공격력으로 환산되지 않는다. 숫자가 나온 정예 기준: 완성 핵탄두 8.2 / 융단 폭격 4.8~5.4 / 미사일 5.8~6.6, 뿌리만 2.9~3.3 / 1.7~2.4 / 1.1~1.3 (다섯 자루 / 섞인 팀). 목표(완성 3, 뿌리 1.5)보다 대체로 세고 미사일 뿌리는 약하다. 기준을 다시 생각해야 한다(예: 처리량이 한계인 무기는 같은 M* 에서의 처치 수나 섞인 팀 M* 의 비 자체를 본다). 융단 폭격 뿌리 1단계는 한 발 38% x 3 이라 적이 드문 곳에서는 맨 포탄보다 약할 수 있다(계산기 0.86). 계산기(`value.js line mortar.N`)는 새 기구 계수 `m.carpet`, `m.shock` 가 영점 전이다.
- 결과 표를 `tools/balance_log.md` 에 적는다.

## T8. 파츠·증강 등급 예산 맞추기 (T3 계산기 결과)
T3 계산기의 "예산에서 크게 벗어난 항목"(`tools/value_report.txt` 끝)을 고친다. 가치는 그 무기에 달았을 때의 종합 가치(공격력 +%), 예산 = 등급 비율 [0.25, 0.5, 1, 2.5] × 같은 칸 종류의 영웅 평균(무기 파츠 21, 증강 52). 영웅 값을 먼저 정하고 등급 비율 1:2:4:10(예외는 balance_log I절)을 따른다. T4 와 T5 가 증강 목록을 바꾸므로 그 뒤에 하는 것이 좋다(T7 보다는 앞).
- 구조를 고칠 것 (설계 판단, 사용자와 고르고 시작):
  - 중화기 개조·경량 프레임·유리 대포: 대가(공격 속도 −15%, 공격력 −10%, 사거리 −15%)가 등급과 상관없이 고정이라 낮은 등급이 손해다. 중화기 일반 −17 / 희귀 −8 / 영웅 +10 / 전설 +63 (예산 5 / 11 / 21 / 53), 경량 일반 −2 / 희귀 +6, 유리 희귀 0 / 영웅 +13. 안: 대가도 등급에 비례하게 하고(예: 중화기 공격 속도 −0.31 × v) 이득을 올려 순가치를 예산에 맞춘다.
  - 처형 모듈·선제 타격기: 문턱(체력 50% 이하, 70% 이상) 때문에 효과에 상한이 있어 높은 등급이 약하다. 처형 5 / 7 / 10 / 12, 선제 8 / 15 / 24 / 27 (예산 5 / 11 / 21 / 53). 안: 등급이 오를수록 문턱도 넓힌다(예: 처형 50 → 60%).
- 값만 고칠 것 (영웅 가치, 예산 52. 계산기로 값을 정하고 측정으로 확인):
  - 강함: 대형 포탄 128, 화염 지대 117, 핵탄두 전설 394(예산 129), 정밀 포격 96, 범위 증폭 99, 다중 투척 104, 철갑 산탄 희귀 75(예산 26).
  - 약함: 표식 6, 감전 6, 냉각탄 15, 정전기장 22, 냉동 광선 22, 충격탄 30, 유도탄 31, 연발 32.
  - 집광(영웅 28, T3 에서 4배로 올린 뒤): 적이 적으면(정예·초반) 잔열보다 세고 물량에서는 +3% 라, 값을 더 올리면 소수 정예에서 지나치게 세진다. 기구를 바꿀지(예: 빔에 맞은 적이 많을수록 보너스 대상도 늘리기) 판단한다.
  - 기지 파츠·증강: 수리 드론·수리 장치·정비반이 강함(예산의 1.7~2.4배), 방패 발생기·행운 부적·절약 회로·감속 철조망이 약함(0.35~0.66배). 교환 비율이 ±50% 라, 먼저 `node tools/surv.js src/core.js 321 24 --pair part:command:2,part:depot:2,part:shield:2,part:drone:2,aug:h_repair:2` 처럼 짝 생존을 다시 재서 `tools/value.js` 의 `PAIR` 에 넣고 `fit` 으로 교환 비율을 좁힌 뒤 고친다.
- 계산기 한계: 둔화·기절·밀치기와 박격포는 계산기 오차가 크다(표본 밖 최대 1.5배, 박격포는 측정 자체도 고르지 않음). 이 항목은 고친 뒤 꼭 `node tools/item_eq.js --only <무기>,<id> --grades 0,1,2,3` 으로 잰다. 공용 증강(a_*)은 가장 잘 맞는 무기 기준이다.
- 검증: 바꾼 항목 측정, `node tools/value.js fit` 으로 계수 갱신, `node tools/surv.js src/core.js 321 48` 중앙값을 바꾸기 전과 비교해 `tools/balance_log.md` 에 적는다.
