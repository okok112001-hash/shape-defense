# 밸런스 벤치 (tools/bench.js)

같은 적 등장 순서(시드 고정)에서 구성만 바꿔 기지가 받는 피해(leak)를 비교하는 헤드리스 시뮬레이터입니다. 두 가지 모드가 있습니다.
- 시나리오 모드(`all`, `weapons`, `augs`, `parts`): 정해진 팀으로 130초씩 싸워 보는 짧은 실험
- 전체 게임 모드(`run`): 시작부터 15분까지 표준 봇이 실제로 플레이하는 긴 실험

## 사용법 (저장소 루트에서 실행)
- `node tools/bench.js all`            무기, 증강, 파츠를 모두 측정 (기본 시드 5개, 등급은 모두)
- `node tools/bench.js weapons|augs|parts`   한 묶음만 측정
- `node tools/bench.js skills [--runs 4 --tag x]`  진화 스킬 12줄의 강도 (다섯 블래스터 팀 대비 leak 변화, 목표 -30%~-60%). `--only blaster.0` 처럼 줄만 지정 가능. 레인 포화로 레인 한정 스킬이 0 가까이 나오므로 세기 비교는 아래 `skill_eq.js` 를 쓴다
- `node tools/bench.js run`            전체 게임 모드 (기본 시드 8개, 등급은 최저와 3만)
- `node tools/bench.js calibrate`      적 체력 보정만 새로 계산해 `tools/bench_cal.json` 에 저장
- 옵션
  - `--runs N`        시드 개수 (시드는 1..N)
  - `--only a,b`      id가 일치하는 대상만 (무기 id, 증강 id, 파츠 id 모두 해당)
  - `--grades ends|all|0..3`   `ends` = 최저 등급과 전설만, `all` = 최저 등급부터 전설까지 전부, 숫자(0~3) = 그 등급만(항목의 최저 등급이 더 높으면 그 최저 등급). 시나리오 모드 기본 all, run 모드 기본 ends
  - `--tag 이름`      결과 파일 이름에 `_이름`을 붙여 기본 리포트를 덮어쓰지 않음
  - `--recal`         저장된 보정을 무시하고 전부 다시 계산
  - 환경변수 `BENCH_CORE=경로`   다른 core.js 로 가정 실험(probe)할 때. 값 몇 개만 바꿔 보려면 core.js 를 불러온 뒤 환경변수 `PROBE` 의 JS(변수 `Core`)를 실행하는 작은 래퍼 모듈을 만들어 `BENCH_CORE` 로 주면 된다 (예: `Core.AUGS.a_dmg.v[2]=41;`)

산출물: `bench_report.txt`(표와 요약), `bench_summary.json`(튜닝 판정용 요약), `bench_raw.json`(원자료), `bench_run.json`(run 모드 요약), `bench_cal.json`(보정 캐시). 튜닝 기록은 `balance_log.md`.

## 시나리오 모드
- 시나리오 5개: few(소수 정예), swarm(물량), mix(표준 혼합), boss(보스전), early(초반). 각각 워밍업 10초 + 측정 120초, 기지는 죽지 않음. 보스전은 보스 체력 배수 1.0의 거대체(전력 보스)가 나옵니다.
- 셀 "a / b" = 기준팀 대비 leak 변화% / 총 dmg 변화%. leak은 음수가 좋다. "~" 는 잡음 범위 안(같은 시드끼리 짝지은 t검정). 마지막 열은 다섯 시나리오 평균.
- 비교 대상
  - 무기: [블래스터, 블래스터, X, 블래스터, 블래스터] 대 블래스터 5자루
  - 증강: 무기 T 두 자루(슬롯 1, 3)에 증강을 달고 나머지는 블래스터. 기준 = 증강 없는 같은 팀
  - 파츠: [산탄포, 블래스터, 레이저, 전격기, 박격포] 전원에 파츠 1개씩. 기준 = 파츠 없음
- 적 체력 배수 M 보정: M은 (기준팀, 시나리오)마다 따로 맞춥니다. 보정 해시에는 600초 시점 가중치(`DEFW`)가 들어갑니다. 벤치가 `hpMul`/`spawnWeights` 식을 덮어쓰므로 `BAL.hpMul`의 K를 바꿔도 보정은 낡지 않지만, 적 등장 비율(예: `BAL.runnerTau`)을 바꾸면 다시 계산됩니다. 그 기준팀이 무기 없을 때 피해의 약 45%만 받도록 이분법으로 찾고, 결과를 `bench_cal.json`에 `팀|시나리오` 키로 저장합니다. 저장 항목에는 팀에 든 무기 정의, 적 정의, 시나리오, 체력 곡선의 해시가 들어 있어, 이 중 하나가 바뀌면 해당 항목만 자동으로 다시 계산됩니다. 파츠/증강 수치를 바꾸는 것은 기준팀에 영향이 없으므로 보정을 다시 하지 않습니다.
- 계단 현상: leak은 적을 죽이는 타수 문턱을 넘을 때 계단처럼 변합니다. 보정은 계단 모서리가 아니라 같은 비율이 이어지는 구간 안쪽 값을 고릅니다. 팀 한쪽에 레인을 막는 무기가 있으면(예: 박격포/저격포 팀의 swarm) M을 아무리 낮춰도 목표 비율에 닿지 않을 수 있고, 그 칸은 사실상 포화입니다(리포트의 M 표에서 괄호 안 비율로 확인).
- 포화: 증강은 두 슬롯에만 달리므로, 단일 레인 무기(레이저 등)는 그 레인에서 새는 피해를 다 없애면 더는 줄일 수 없습니다. 이 한계를 넘는 변화는 측정되지 않습니다.
- 결정성: `Core.seed(n)` 이 난수 세 갈래를 따로 시드합니다. `rndS`는 적 등장(종류, 레인, 위치), `rnd`는 전투(치명타, 효과), `rndG`는 전리품과 성장(생성, 파츠 굴림, 제조, 보스 보상, 증강 선택지, 강화 성공/절약)입니다. `rndG`는 굴림 한 번에 값 하나만 뽑아 쓰므로 같은 시드면 전투와 상관없이 k번째 생성/굴림 결과가 같습니다. 벤치는 모든 구성에서 등장 순서 해시가 같은지 매번 검사해 리포트에 적습니다.

## 전체 게임 모드 (`run`)
- 시드마다 t=0부터 15분(54000 스텝)을 `tools/bot.js` 의 표준 봇이 플레이합니다. 봇은 Math.random을 쓰지 않으며 자기 난수열(시드에서 파생)만 씁니다. 적 곡선은 게임 그대로이고, 기지는 죽지 않습니다(leak은 세고, 매 스텝 hp를 되돌립니다. 그래서 체력 회복/최대 체력 계열은 leak에 잡히지 않습니다).
- 대상은 시작할 때 공짜로 줍니다: 무기 파츠/증강은 처음 블래스터에, 기지 파츠는 기지 파츠 칸에, 기지 증강은 `S.base.augs`에. 봇이 이 대상을 교체하거나 녹이지 않도록 고정합니다. 같은 시드에서 대상 없는 게임과 짝지어 비교합니다.
- 지표: 15분 총 leak, 팀 화력(`stats(w).dmg / stats(w).cd` 합)의 5/10/15분 값, 얻은 조각과 재화 총량(쓴 것 포함).
- 기준 대상으로 무기 파츠 `dmg`와 증강 `a_dmg`가 같이 들어갑니다. 기지 파츠/증강과 `gold`는 같은 등급의 `dmg`와 비교해 0.5배에서 1.5배 안이어야 한다는 기준을 씁니다(leak이 둔감하면 15분 화력 변화로 비교).
- 결정성 검사: 같은 (대상, 시드)를 두 번 돌려 leak, 화력, 재화, 조각, 생성 로그, 최종 상태 해시가 완전히 같은지 리포트에 적습니다. 또 같은 시드에서 대상 유무와 상관없이 앞 20번 생성 결과가 같은 비율도 적습니다(100%가 아닌 것은 봇의 무기 수나 인벤토리가 달라져 생성 확률이 달라지는 경우).
- 잡음 주의: 15분 게임은 한 번의 차이가 끝까지 번져서 시드 간 편차가 큽니다. 시드 6개 기준으로 아무 효과가 없는 대상도 화력이 몇 % 흔들립니다. leak은 대부분 초반과 마지막 몇 분에 몰려 있어 더 불안정합니다. "~" 표시가 없는 칸만 믿을 수 있습니다.

## 봇 (`tools/bot.js`)
0.5초마다 생성(최대 6회), 무기 장착, 파츠 부착/교체/용해, 제조(게이지가 되는 대로. 제조할 때마다 비용이 오르고 확률이 좋아진다), 강화(최대 40회), 증강 선택(최고 등급을 고르되 30%는 봇 난수로 무작위), 기지 강화를 합니다. `/tmp/sim/sim3.js` 의 봇을 옮긴 것입니다.

## 생존 측정 (`tools/surv.js`)
표준 봇이 기지가 죽을 때까지(최대 60분) 전체 게임을 플레이하고 생존 시간을 잽니다. 시드 고정이라 같은 입력이면 결과가 같습니다. 작업은 CPU 수만큼 나뉘어 병렬로 돕니다.

`node tools/surv.js <core.js> <K> <시드수> [옵션]`
- 기본 출력: 평균, 사분위, 최소/최대, 100강 도달 판 수, 5분 안에 죽은 판 수. K는 `BAL.hpMul` 식 `pow(1+pow(t/K,3.1),0.9)*exp(0.0012t+(t/3400)^2)` 의 시간 상수 `BAL.hpK` 입니다(전체 난이도 조정용. 식은 core.js 한 곳에만 있고 surv.js 는 `BAL.hpK` 만 바꿉니다).
- `--runner C`: `BAL.runnerTau`(달리는 적 비율이 늘어나는 시간 상수, 초)를 바꿔 봅니다.
- `--pair 항목,항목`: 짝지은 생존 비교. 항목은 `part:ID:등급`(기지 파츠 칸 0) 또는 `aug:ID:등급`(기지 증강 칸 0)입니다. 시작할 때 공짜로 주고(봇이 교체/용해하지 않게 고정) 같은 시드의 비교 게임과 생존 시간 비율의 기하평균을 냅니다. gain = 비율 - 1, 옆의 se는 로그 비율의 표준오차입니다.
  - 비교 게임: 기지 파츠는 효과 없는 자리표시 파츠를 같은 칸에 준 게임, 기지 증강은 같은 증강을 수치 0으로 준 게임입니다. 칸을 비워 두면 봇이 칸을 다르게 채워 결과가 크게 갈리고, 증강은 이미 가진 같은 증강을 선택지에서 빼기 때문에 치우침이 생깁니다.
  - `항목@값[/둘째값]`: 그 등급의 수치(`v`, 둘째 수치 `w`가 있으면 `w`)를 임시로 바꿔 잽니다. 예: `part:armor:2@8/4.4`, `aug:h_repair:2@0.08/3`. 수치를 튜닝할 때 core.js 를 고치지 않고 후보를 한꺼번에 잴 수 있습니다.
  - 시드 24개의 평균이라 한 시드의 초반 사망이 20분 생존으로 바뀌면 gain이 5~7% 움직입니다. 값을 조금 바꿔도 gain이 계단처럼 뛰므로 se를 함께 보세요.
- `--pact 목록|all`: 천칭 거래 확인. 대상 없는 게임이 10분(600초)을 넘긴 시드만 골라 600초에 `Core.choosePact`로 거래를 적용하고, 이후 생존 시간(T-600)의 비율을 기하평균으로 냅니다. `거래@키=값;키=값`으로 `Core.PACT` 수치를 임시로 바꿔 볼 수 있습니다(예: `glass@glassDmg=1.2;glassHp=0.7`). 현자의 눈(건너뛸 수 없음)에서 봇이 멈추지 않게, 증강 선택이 남으면 첫 선택지를 고르고 칸이 차면 가장 낮은 증강을 교체합니다.
- `--cache 파일`: 짝지은 비교 게임의 결과를 저장해 두었다가 재사용합니다(키: core.js 내용 해시, K, 시드 수, 비교 게임 종류). `--nobase`: 일반 게임 첫 줄을 건너뜁니다. `--eval 코드`: core.js 를 불러온 직후 실행할 JS(`Core` 변수). `--json 파일`: 시드별 결과 저장.
- 봇이 쓰지 못하는 거래(용광로, 집중, 유물 등)는 측정은 하되 수치 조정 대상이 아닙니다.

## 진화와 스킬 점검 (`tools/evo_test.js`)
`node tools/evo_test.js [core.js] [--quick]` 진화 조건과 비용, 진화 직후 능력치 연속성, 강화 비용 100 + 5 x 일반 비용, 5강마다 스킬 포인트, 선행 조건, 모든 노드 x 모든 랭크의 능력치 변화(NaN 없음), 새 노드 동작, 진화 해제(부식, 도박사, 유물), 모두 분해 제외, 무기 종류마다 20분 스트레스(`--quick`은 2분)를 확인한다.
봇은 기본으로 100강이 되면 진화하고(진화 비용을 모으는 동안 다른 강화는 미룬다) 스킬을 즉시 찍는다. `node tools/surv.js src/core.js 321 48 --noevo` 는 진화를 끈다(진화 도입 전과 같은 결과).

## 스킬 등가 화력 (`tools/skill_eq.js`)
진화 스킬 줄의 세기를 "공격력 몇 %어치인가"로 잰다. `bench.js skills` 는 진화 무기 하나가 자기 레인을 다 잡아 leak 이 포화하므로 이 도구를 쓴다.
- 방법: 팀 = 같은 무기 5자루, 모두 진화 0강(파츠, 증강 없음), 다섯 자루에 같은 스킬. 시나리오는 bench 의 5개(`runSim` 을 그대로 불러 쓴다). 시나리오마다 팀이 무기 없을 때 피해의 45%만 받는 적 체력 배수 M\* 를 찾는다(구간 잡기, 이분법, 마지막에 ±7.5% 안 7점 직선 맞춤). R = M\*(스킬) / M\*(스킬 없음).
- 계단 현상: 적 체력이 모두 같으면 leak 이 타수 문턱마다 크게 계단져 R 이 수십 % 흔들린다. 그래서 적마다 체력에 exp(±0.2) 범위의 고정 배수를 곱한다(등장 시각, 종류, 레인, 위치, 시드의 해시라 구성이 달라도 같은 적이면 같은 배수. `runSim` 의 선택 인자 `jit`, bench 자체는 쓰지 않음).
- 방법 검증: 가짜 줄(도구 안에서만 쓰는 파츠) 두 개를 같이 잰다. 공격력 +50% 는 R = 1.50, 효과 없음은 R = 1.00 이 나와야 한다(허용 ±0.05).
- 쓰는 법: `node tools/skill_eq.js` (1차분 12줄 x 완성/뿌리만, 시드 4개, 4코어에서 약 14분). 옵션 `--only blaster.0,laser`(줄 또는 무기, 2차분 무기는 이름을 줄 때만), `--runs N`, `--from S`(시드 S부터, 시드 안정성 확인용), `--root`(뿌리만만), `--full`(완성만), `--nofake`, `--jit 0.2`, `--tag 이름`(결과 `skill_eq_report_이름.txt`).
- 읽는 법: 셀 = 시나리오별 R. 기하평균 R 을 공격력 +(R-1)%, 진화 강화 ln R / ln 1.03 단계로 환산한다. "오차%" = 직선 맞춤의 표준오차(남은 계단 크기), "*" = 창을 옮겨 다시 맞춤, "!" = 옮겨도 창 밖이라 잘림(믿기 어려움), "포화" = M=1e7 에서도 45%만큼 새지 않음(밀어내기 고정처럼 체력과 상관없이 막는 효과, R 무한대), "못버팀" = 그 반대. 마지막 줄의 결과 해시가 같으면 결과가 같다.
- 한계: 같은 무기 5자루 팀 기준이라 군중 제어가 다섯 겹으로 쌓이고(예: 슬러그 밀어내기), 섞인 팀의 시너지(다른 무기에 거는 약화 등)는 다르게 나올 수 있다. 처리량이 모자란 무기는 기준을 못 잡는다(예: 박격포 5자루는 적 체력이 0.01배여도 57~77%가 새서 "못버팀", 2차분을 잴 때는 목표 비율을 따로 정해야 함). 가짜 줄 검증은 순수 배율이라 계단 완화의 정밀도까지는 보여 주지 못한다(그건 "오차%" 와 `--from 5` 비교로 본다). 기지 체력/회복처럼 leak 에 안 잡히는 효과, 보스 예고 회피는 재지 않는다. 시드 4개의 표본 차이는 `--from 5` 로 따로 확인한다.
- `--mix` (T5a): 섞인 팀 [블래스터, W, 블래스터, W, 블래스터](모두 진화 0강, 블래스터는 스킬 없음), 운반 칸 1, 3 에만 스킬. 운반 칸 공격력 +100/+300/+700/+1500% 가짜 마디의 ln M\* 꺾은선에서 같은 M\* 가 되는 공격력 배수를 R 로 읽는다(같은 무기 팀 R 과 같은 뜻, 검증은 가짜 +50% → 1.50). "평평" = 16배로 올려도 팀 M\* 가 1.5배도 안 움직여 환산 불가, ">16" = 가장 높은 마디 위. 박격포 측정은 약 1분.
- M\* 찾기(`findM`)와 워커 실행기는 `tools/eq_lib.js` 에 있고 `item_eq.js` 와 같이 쓴다.

## 파츠·증강 등가 화력 (`tools/item_eq.js`)
파츠와 증강의 세기를 "운반 무기의 공격력 +몇 %어치"(eq)로 잰다. 결과 `tools/item_eq.json` 은 `value.js fit` 이 영점 맞춤에 읽는다.
- 팀: X2(T) = [블래스터, T, 블래스터, T, 블래스터], 운반 칸 1, 3 (레이저만 I5 = 레이저 다섯 자루, 다섯 모두 운반. X2 에서는 레이저가 자기 레인을 다 비워 가짜 꺾은선이 평평해진다). P5 = bench 의 파츠 팀 [산탄포, 블래스터, 레이저, 전격기, 박격포], 다섯 모두 운반. 무기는 진화하지 않은 보통 무기.
- 대상(기본 영웅, 최저 등급이 전설이면 전설): X2/I5 는 그 무기 증강 풀 전부(a_dmg 제외)와 파츠 rate, range, boss, exec, first, chill, ember. 범위 무기(레이저, 펄스, 박격포, 산성)는 spread, nolimit 도. P5 는 무기 파츠 전부(dmg, gold 제외).
- json 의 `meta.caps` 는 측정할 때 무기별 최대 타격 수다. 없으면 T4(최대 타격 수) 전의 측정이라 `value.js` 가 제한 없이 계산한다(스킬 리포트는 `skill_eq_report.txt`, `_s5`, `_t3` 가 T4 전).
- 환산: M\* 는 skill_eq 와 같은 방법. 같은 팀의 기준(공격력 +0)과 가짜 파츠 +25/+100/+300% 의 ln M\* 를 ln(1+공격력)에 대한 꺾은선으로 보고, 대상의 ln M\* 에 맞는 공격력을 찾는다. 가짜 +50% 를 보간해 50 ± 5 가 나오는지로 검증한다.
- 쓰는 법: `node tools/item_eq.js` (구성 약 180개, 시드 4개, 4코어에서 약 30분). 옵션 `--only laser,P5,rate`(무기 id, P5, 항목 id), `--runs N`, `--from S`, `--jit 0.2`, `--grades 0,2,3`, `--nofake`(검증용 d50 만 뺀다), `--tag 이름`.
- 읽는 법: 셀 = 시나리오별 eq(%). "천장" = 가짜 꺾은선이 평평해지는 곳(운반 무기가 이미 한 방에 잡는 등)보다 높아 공격력으로 환산할 수 없음, "^" = 천장에 닿아 eq 는 하한, n/a = 기준 M\* 를 못 찾음.
- 한계: X2 는 운반 두 자루라 군중 제어, 취약처럼 다른 무기를 돕는 효과도 운반 무기의 값으로 센다(운반 칸 피해 비율을 함께 적는다). 박격포/저격포 X2 는 물량(swarm)에서 기준을 못 잡는다. 시드 4개라 작은 차이(±3%p)는 잡음이다.

## 수치 가치 환산 (`tools/value.js`)
모든 파츠, 증강(등급별), 진화 노드(랭크별), 기지 항목을 "공격력 +1% = 화력 가치 1" 단위로 계산한다. 사용자용 설명은 `docs/value.md`.
- 방법: 항목을 core.js 의 진짜 능력치(`stats`)에 적용하고, 무기마다 처치 속도 식(적 밀도, 처치 타수, 보스 비중, 군중 제어 계수 ...)으로 "적 체력이 몇 배여도 맨 무기만큼 잡는가"(R)를 푼다. 가치 = (R-1) x 100. skill_eq 와 item_eq 의 R/eq 와 같은 뜻이다. 계수는 `tools/value_cal.json`.
- 쓰는 법: `node tools/value.js` (표와 예산 밖 목록 → `tools/value_report.txt`), `node tools/value.js item b_frost 2` (항목 하나, 시나리오별), `node tools/value.js line laser.0 0.5` (스킬 줄 하나의 랭크별 누적 R, 배율 sc 를 바꿔 본다). 환경변수 `VALUE_CORE=경로` 로 다른 core.js 를 계산할 수 있다(수치를 바꿔 보기).
- 영점 다시 맞추기: `node tools/item_eq.js` 와 `node tools/skill_eq.js` 를 새로 잰 뒤 `node tools/value.js fit` (계수 → `value_cal.json`, 예측과 측정 비교 → `value_fit.txt`). 스킬 자료는 `skill_eq_report.txt` 위에 `skill_eq_report_t3*.txt` 를 덮어 쓴다. 기지 항목의 교환 비율은 코드 안 `PAIR`(balance_log 의 짝 생존 기록)로 맞춘다.

## 스킬 성능 (`tools/skill_perf.js`)
`node tools/skill_perf.js [core.js] [--secs 60]` 진화 무기 다섯 자루에 스킬을 모두 찍은 팀과 스킬 없는 팀을 60초 돌려 시간 비율을 낸다(적이 죽는 경우, 죽지 않는 경우).
