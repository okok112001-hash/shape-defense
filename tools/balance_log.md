# 밸런스 조정 기록

밸런스 벤치(tools/bench.js)로 측정하고 숫자만 고쳤다. 메커니즘, `BAL` 곡선, 보스 규칙은 건드리지 않았다. 측정은 시나리오 모드(시드 4~5개)와 전체 게임 모드(시드 8~20개)이고, 밴드 밖 항목 수는 잡음을 허용하지 않은 엄격한 기준이다.

## 진행 요약

| 단계 | 한 일 | 밴드 밖 항목 (전체 327행: 무기 7, 증강, 파츠 포함) |
|---|---|---|
| 측정 0 | 원래 값, 기준팀마다 보정 (시드 4) | 174 |
| 패스 1 | 무기 dmg 4개, 파츠/증강 v 35개, c_corrode 단위 오류 수정, core 파츠 v 연결 | 150 |
| 패스 2 | 파츠/증강 v 31개 + 개수형 증강의 연관 피해% 상수 8개 | 93 |
| 패스 3 | v 10개 + 상수 4개(extraShotMul, m_barrage, p_orbs 재조정, m_shrap 신규) | 83 |
| 최종 확인 | 시드 5개로 다시 측정 (조정 없음) | 85 (이 중 gold 4행은 run 모드에서 판정하는 항목이라 제외 대상) |

전체 게임 모드(기지 파츠/증강, gold)는 별도로 3번 조정했다: 측정(r2, 20시드) -> 조정 -> 측정(r3) -> 조정 -> 측정(r4) -> 조정(h_shock 되돌림, gold 상향) -> 최종 표(시드 10). 한 번 조정할 때마다 같은 시드로 다시 측정했다.
무기 dmg를 정하려고 먼저 한 번 가정 실험을 했다(probe): 모든 무기 dmg x1.25를 `BENCH_CORE`로 측정해 무기별 민감도(산탄포 -6.1, 전격기 -7.6, 박격포 -1.9, 산성 분사기 -7.5 leak% 변화)를 얻었고, 이 값으로 패스 1의 dmg를 정했다. 이 측정은 패스에 세지 않았다.

## 기준과 방법

- 밴드: 증강 등급 0..3 = -6..-16, -10..-24, -20..-40, -32..-58 (전설 전용은 -65까지), 파츠 = -5..-14, -9..-22, -16..-34, -28..-52, 무기 = -5..-30 (+10% 초과 시나리오는 1개까지).
- 기준팀 보정: 팀마다 무기 없음 대비 약 45% leak이 되도록 M을 따로 맞췄다(tools/bench_cal.json).
- 파츠/증강은 v 배열을 등급별로 독립적으로 고른 뒤 등급 순서를 단조 증가로 보정했다. 반응 곡선은 같은 항목의 4개 등급 측정점을 이어서 보간했고, 공용 증강은 8개 무기 팀 중 밴드 안에 드는 팀이 가장 많아지는 값을 골랐다. 한 번에 바꾸는 폭은 0.4배에서 2.2배, 확률/둔화 상한은 60..100.
- 시나리오 표의 괄호 (a/b) = 밴드 안에 든 팀 수 / 전체 팀 수(공용 증강만).

## 코드에서 고친 것 (숫자 외)

- `c_corrode`(부식액): 효과가 `add('aVuln')`이라 v=5가 +5%p가 아니라 +500%p로 들어가 leak이 -96..-100%였다. 설명(+v%p)대로 `pct('aVuln')`으로 고쳤다. 이것은 단위 오류 수정이고 새 규칙은 없다.
- `core`(코어 증폭기): v 배열이 표시용일 뿐 효과는 코드에 고정(+60%/+30%)이라 v를 조정할 수 없었다. 효과가 v를 읽도록 연결했다(공격력 +v%, 공격 속도 +v/2%). 새 값 v=24.
- 전리품/성장 난수 `rndG` 분리(core.js). 굴림 한 번에 `rndG`에서 값 하나만 뽑는다. 강화는 절약 파츠가 있든 없든 항상 두 값을 뽑는다.

## 기지 파츠/증강, gold (전체 게임 모드)

## C. 방어 기지 항목: 두 가지 능력 (코드 + 영웅 수치 조정)

### 코드 변경
- 이전(값이 고정이라 끝없는 게임에서 커지지 않음): `armor` 기지 최대 체력 +[15, 30, 50, 80], `drone` [8, 6, 4, 3]초마다 체력 1 회복, `heal` 처치 시 [0.4, 0.7, 1.1, 1.8]% 확률로 체력 1 회복, `h_armor` 최대 체력 +[20, 40, 70, 110], `h_repair` [6, 4.5, 3.5, 2.5]초마다 체력 1 회복.
- 새 구조: 항목마다 등급별 배열이 둘이다. `v` = 첫째 수치, `w` = 둘째 수치. `ap(s, v, w)`, `d(v, w)`. `stats()`/`bstats()`/`partDesc`/`augDesc`가 둘을 함께 넘긴다. 화면(`ui.js`)은 모두 `partDesc`/`augDesc`를 거치므로 인벤토리 정보 줄, 비교 창, 기지 창, 증강 선택 창이 그대로 새 문장을 보여 준다.
  - `armor` 장갑판: "기지 최대 체력 +a% · 모든 무기의 공격력 +b%" (`hpPct`, `dmgAll`)
  - `drone` 수리 드론: "1초마다 최대 체력의 a% 회복 · 재화 획득 +b%" (`regenPct`, `goldAll`)
  - `heal` 수리 장치: "적을 처치할 때 a% 확률로 최대 체력의 1% 회복 · 보스를 처치하면 체력 b% 회복" (`heal`, `bossHeal`)
  - `h_armor` 강화 장갑: "기지 최대 체력 +a% · 기지가 받는 피해 -b%" (`hpPct`, `dmgRed`. 피해 감소는 방패와 곱으로 쌓인다: 받는 피해 x (1-방패) x (1-b))
  - `h_repair` 정비반: "1초마다 최대 체력의 a% 회복 · 보스를 처치하면 체력 b% 회복" (`regenPct`, `bossHeal`)
  - 최대 체력 = round((100 + 4 x 강화 단계) x (1 + hpPct)). 회복은 매 틱 연속으로(초당 최대 체력의 a%) 들어간다. 보스 처치 회복은 `kill()`에서.
- `ui.js` 기지 창 머리줄: 예전 "N초마다 회복"(= 1/regen)을 "초당 체력 a% 회복"으로, "받는 피해 -X%"는 방패와 기지 증강 피해 감소를 합친 값으로 바꿨다.
- 같은 방식으로 두 번째 수치가 필요한 항목 3개도 `w`로 분리했다(수치는 그대로): `critd`(치명타 피해 v%, 치명타 확률 w%. 예전 `CRITD_CHANCE` 표는 v를 열쇠로 써서 등급마다 값을 바꿀 수 없었다), `b_seek`(조준 레인 v, 공격력 w%. 예전 w = v/8 x 100), `t_wide`(레인 v, 공격력 w%. 예전 w = v x 10). E단계에서 연관 피해%에 비율을 적용하려고 한 것이다.

### 측정 방법 (tools/surv.js `--pair`)
- 시작할 때 기지 파츠 칸 0 또는 기지 증강 칸 0에 항목을 주고(봇이 바꾸지 않게 고정) 같은 시드에서 항목이 없는 게임과 생존 시간(S.t)을 비교한다. 지표 = T_with / T_without 의 기하평균, gain = 비율 - 1. 시드 24개(1..24), K = 300.
- 처음 만든 "항목 없음" 기준은 칸을 비워 두는 것이었는데, 같은 시드에서도 항목 유무에 따라 봇이 기지 칸/증강 선택지를 다르게 채워서 결과가 크게 갈렸다(항목 `armor`를 효과 0으로 줘도 시드별 비율 0.80..1.00, 증강은 +13~14%의 치우침). 그래서 기준을 다음처럼 바꿨다.
  - 기지 파츠: 효과 없는 자리표시 파츠를 같은 칸에 줌 (효과 0짜리 `armor@0/0` gain -1.0%, `heal@0/0` +2.0%, `wire@0` -3.1%, `drone@0/0` -3.7%).
  - 기지 증강: 같은 증강을 수치 0으로 쥠. 증강 선택지는 이미 가진 같은 증강을 빼고 나오기 때문에 자리표시로는 선택지가 달라져 `h_armor@0/0` +14.1%, `h_repair@0/0` +13.1%의 치우침이 생겼다.
- 시드 24개의 평균이라 항목 효과가 같아도 값을 조금 바꾸면 gain이 크게 흔들린다(예: wire 27 -> -4.5%, 29 -> +10.5%, 35 -> +22.8%. 한 시드의 초반 사망이 20분 생존으로 바뀌면 기하평균이 약 5~7% 움직인다). 이 때문에 "허용 범위 안"은 이 시드 24개에서 잰 값이라는 뜻이다. 표준오차는 gain 표기 옆의 se(%)로 함께 적었고, 방어 전용 항목도 3~12% 수준이다.

## E. 등급 비율 1 : 2 : 5 : 15
규칙: 등급별 값 = 영웅 값 x [0.2, 0.4, 1, 3] (소수점 둘째 유효숫자로 반올림, 영웅 값은 반올림하지 않고 그대로). 적용 대상은 파츠/증강(무기, 기지)의 모든 수치 배열(`v`, 있으면 `w`)이고, 최소 등급(`min`) 미만은 0. 구현은 영웅 값을 읽어 `v`/`w`를 고쳐 쓰는 일회용 스크립트로 했다. `min` 3인 항목은 그대로.
바뀐 항목 수: 75 (파츠/증강 합계, 예외 포함). 이전 -> 새 값 전체 표는 이 절 끝.

### 예외 (이유와 처리)
- 간격(낮을수록 좋음): `h_wave` 빙결 파동 [0, 0, 30, 18] -> [0, 0, 30, 10] (속도 3배 = 간격 1/3. 하한 없이 영웅/3 = 10초. 아래 -78% 점검 대상 아님: 기지 증강은 시나리오 벤치로 잴 수 없음).
  (`drone`, `h_repair`는 예전엔 간격이었지만 이번에 "초당 최대 체력의 %"로 바뀌어 일반 값과 같이 처리했다.)

## P. 후반 난이도: 적 체력 식, 보스 체력, 기지 피해 (재보정 전)
- 이유: 후반 긴장감, 보스를 조금 더 단단하게, 기지 피해가 시간에 따라 커지게. 모두 끊기지 않는 식 하나.
- 적 체력 `BAL.hpMul(t)`: `pow(1+pow(t/K,3.1),0.9)*exp(0.0012t)` -> `pow(1+pow(t/K,3.1),0.9)*exp(0.0012t + (t/2400)^2)`. 추가 배수는 10분 x1.06, 20분 x1.28, 30분 x1.75, 40분 x2.72. 시간 상수는 `BAL.hpK = 321` 로 뺐고, `surv.js` 는 식을 덮어쓰지 않고 `BAL.hpK` 만 바꾼다.
- 보스 체력 `BAL.bossHp`: 1.3 -> 1.43.
- 기지 피해 `BAL.leakMul(t) = 1 + (t/720)^1.5` 신설. 적이 기지에 닿는 순간의 `S.t` 로 `e.leak` 에 곱한다(반올림은 그대로). 5분 x1.27, 10분 x1.76, 20분 x3.15, 30분 x4.95.
- 벤치: `bench.js` 는 leak 을 기지 체력 변화로 세므로 `init()` 에서 `BAL.leakMul = () => 1` 로 끈다. 시나리오 모드 결과는 변경 전 코드와 완전히 같고(`weapons --runs 1 --only laser` 리포트, 요약 일치) 새 보정 0개, `bench_cal.json` 그대로. `run` 모드는 게임 곡선을 그대로 쓰므로 체력 식과 보스 체력 변화는 반영된다(다시 재지 않음).
